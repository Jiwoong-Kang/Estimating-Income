### 2. `max_depth`가 뭔가

- 트리가 질문을 **몇 단계까지** 나눌지.
- 작음 → 단순(과소적합 가능) / 큼·`None` → 깊게 자람(과적합 쉬움)
- 후보: `[3, 5, 8, 12, 15, 20, None]` (`None` = 깊이 제한 없음)

### 3. CV 결과 (`max_depth` 후보)

| max_depth | CV F1 mean (±std) |
|---|---|
| 3 | 0.613 (±0.005) |
| 5 | 0.620 (±0.006) |
| 8 | 0.645 (±0.006) |
| 12 | 0.662 (±0.005) |
| **15** | **0.667 (±0.014)** ← 선택 |
| 20 | 0.659 |
| None | 0.620 (±0.008) |

- 깊이 3→15까지 F1이 오르다가, **20·`None`은 다시 떨어짐** → 너무 깊으면 과적합.
- **`15`가 `12`보다 CV F1이 조금 더 높음** (0.667 vs 0.662). 다만 std는 15가 더 큼.

  - depth=12보다 고소득(TP)을 더 잡음 (2131 → 2459), 대신 FP도 늘음 → **F1·균형 정확도↑, 정확도·ROC는 12가 나을 수 있음**
- 선택 지표가 **F1**이므로 최종은 **`15`**. (`decision_tree_depth15.json`)
- depth=12 파일은 참고용으로 남을 수 있음.

- 독립 가정 문제는 여전할 수 있지만, 스무딩만으로도 지표가 꽤 바뀜

### 8. Logistic Regression 튜닝에서 배운 것

- 손잡이: **`C`** — 규제 세기 (기본 L2). SVM의 `C`와 같은 역할
  - `C` 큼 → 규제 약함 / `C` 작음 → 규제 셈
- 고정: `max_iter=1000`, `random_state=42`
- 후보: `[0.01, 0.1, 1, 10, 100]`, 선택 지표: CV **F1 mean**

### 9. Logistic CV 결과 (`C` 후보)

| C | CV F1 mean (±std) |
|---|---|
| 0.01 | 0.633 (±0.007) |
| 0.1 | 0.645 (±0.008) |
| 1 | 0.648 (±0.008) |
| **10** | **0.648 (±0.008)** ← 선택 |
| 100 | 0.648 (±0.008) |

- `C≥1`에서는 F1이 **거의 같음**. `10`이 아주 미세하게 제일 높아서 선택.
- 예전 기본 `C=1`과 실무상 차이 거의 없음 → **튜닝으로 큰 점프는 없음** (SVM과 비슷한 패턴).
