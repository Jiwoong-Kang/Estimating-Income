# 2026-10-12

### 1. 프로젝트 방향 잡기

- 이 과제의 핵심은 모델을 많이 돌리는 것보다, **결과가 왜 그렇게 나왔는지 데이터의 특성과 연결해서 설명하는 것**이다.
- 모델 하나마다 아래 흐름으로 정리하면 "what works / what doesn't"와 "배운 점"이 자연스럽게 채워진다.
  1. 실험 전 예상: 모델의 가정과 데이터 특성을 비교해서 잘 될지 미리 예상한다.
  2. 실험: 전처리, 하이퍼파라미터, 설정을 바꿔가며 비교한다.
  3. 결과: 모든 모델을 같은 평가 지표로 정리한다.
  4. 해석: 예상이 맞았는지, 왜 그런지 설명한다.
  5. 배운 점: 새로 알게 된 것, 예상과 달랐던 것을 적는다.
- 모든 모델은 같은 train/test 분할, 같은 평가 방식으로 비교해야 공정하다.
- 항상 다수 클래스(50K 이하)만 예측하는 Dummy 모델도 정확도가 약 76%가 나온다. 그래서 **불균형한 데이터에서는 정확도만 보면 안 된다.**

### 2. 데이터셋: UCI Adult (Census Income)

- 출처가 확실한 UCI Machine Learning Repository의 데이터를 사용한다.
- 목표: 한 사람의 정보(나이, 학력, 직업 등)로 연소득이 50K보다 많은지 적은지 맞히는 **이진 분류** 문제.
- 학습 데이터 32,561명, 테스트 데이터 16,281명, 정보 항목 14개 + 정답 1개.
- 원본 파일에는 주의할 점이 있다.
  - 첫 줄에 항목 이름(헤더)이 없다. 이름은 `adult.names` 설명서를 보고 직접 붙여야 한다.
  - 값 앞에 공백이 붙어 있다. (`39, State-gov, ...`)
  - 빈 칸이 `?`로 표시되어 있다.
  - 테스트 파일 첫 줄은 데이터가 아닌 `|1x3 Cross validator`라는 줄이다.
  - 테스트 파일 정답 끝에 마침표가 붙어 있다. (`<=50K.`) 지우지 않으면 정답 종류가 4개로 잡힌다.

### 3. 수업에서 배운 모델과 이 데이터의 관계

지금까지 배운 모델: Linear/Polynomial Regression, Perceptron, SVM, k-NN, Decision Tree, Naive Bayes.

| 모델 | 이 데이터에서 볼 핵심 포인트 |
|---|---|
| Linear / Polynomial Regression | 이진 분류에 회귀를 쓰면 생기는 문제, polynomial 차수에 따른 과적합 |
| Perceptron | 선형으로 나뉘지 않는 데이터에서 수렴하지 않는 문제 |
| SVM | linear와 RBF kernel 비교, 큰 데이터에서의 학습 시간 |
| k-NN | scaling의 영향, 차원의 저주, k 선택 |
| Decision Tree | 깊이에 따른 과적합, 트리 시각화로 해석 |
| Naive Bayes | "항목끼리 독립"이라는 가정이 깨졌을 때의 영향 |

- CNN은 이미지처럼 이웃한 값끼리 의미가 있는 데이터에 쓰는 모델이라 이 데이터에는 맞지 않는다.

### 4. EDA (Exploratory Data Analysis, 탐색적 데이터 분석)

- 모델을 만들기 전에 **데이터의 형식과 특징을 파악하는 단계**다.
  - 형식: 파일이 어떻게 저장되어 있는지 (구분자, 헤더 유무, 빈 칸 표시 방법)
  - 특징: 빈 칸 개수, 정답 비율, 값의 분포, 평균과 분산, 항목 사이의 관계
- 데이터를 한 줄씩 보는 게 아니라 **코드로 전체를 요약해서 표와 그래프로 본다.**
- 가장 중요한 건 결과를 보고 **모델링에 어떤 의미가 있는지 해석하는 것**이다. 여기서 알아낸 사실이 나중에 모델 결과를 설명하는 근거가 된다.

### 5. 프로젝트 정리 방법

- **폴더 구조:** 여러 곳에서 공통으로 쓰는 코드(데이터 불러오기)는 `src/`에, 분석은 노트북으로 나눈다. 같은 코드를 여러 파일에 복사하면 실수하기 쉽고 고치기도 어렵다.
- **Jupyter 노트북:** 필수는 아니지만, 코드와 그래프와 해석을 한 파일에 같이 둘 수 있어서 데이터 분석에 편하다.
- **`.gitignore`:** Git에 올리지 않을 파일 목록. 기본 템플릿에서 이 프로젝트에 필요한 것만 남겼다. (Python 캐시, 가상환경, 모델 파일, `.DS_Store` 등)

### 6. 가상환경

- 프로젝트 전용 Python 라이브러리 보관함이다.
- Homebrew로 설치한 Python은 전체 설치를 막아둬서 가상환경 없이는 `pip install`이 거부된다.
- 다른 프로젝트와 라이브러리 버전이 충돌하지 않고, `requirements.txt`로 같은 환경을 다시 만들 수 있다.

### 7. 데이터 불러오기 코드 (`src/data.py`)

- `Path(__file__).resolve().parent.parent`: 이 파일 위치를 기준으로 프로젝트 폴더를 찾는다. 어디서 실행해도 같은 경로를 가리키게 하기 위해서다.
- `pd.read_csv`의 옵션
  - `header=None`: 첫 줄도 데이터라고 알려준다.
  - `names=COLUMNS`: 항목 이름을 직접 붙인다.
  - `skipinitialspace=True`: 값 앞의 공백을 지운다.
  - `na_values="?"`: `?`를 진짜 빈 값(NaN)으로 바꾼다.
  - `skiprows=1`: 테스트 파일의 첫 줄을 건너뛴다.

### 8. 실수에서 배운 점: 항목 이름 하나가 빠졌을 때

- `COLUMNS`에서 `capital-loss`를 빠뜨렸더니 열이 15개가 아니라 14개로 나왔다.
- pandas는 이름이 하나 모자라도 **오류를 내지 않고**, 맨 앞 값(나이)을 행 번호로 써버린 다음 나머지 이름을 한 칸씩 밀어서 붙였다.
  - 그래서 "age" 칸에 고용 형태가, "workclass" 칸에 가중치 값이 들어갔다.
  - 빈 칸 개수도 엉뚱한 항목에 표시됐다.
- **교훈:** 오류가 안 났다고 맞는 게 아니다. 데이터를 불러온 직후에는 꼭 `df.shape`(행과 열 개수)와 `df.head()`(앞 몇 줄)를 확인하고, 예상한 값과 비교해야 한다.
