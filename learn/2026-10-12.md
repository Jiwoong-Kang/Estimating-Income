### 1. Setting the project direction

- The point of this assignment is less “run many models” and more **explaining why results look that way by linking them to data traits**.
- For each model, this flow fills in “what works / what doesn’t” and lessons learned:
  1. Pre-experiment expectation: compare the model’s assumptions with the data and guess how well it will do.
  2. Experiment: change preprocessing, hyperparameters, and settings and compare.
  3. Results: summarize every model with the same metrics.
  4. Interpretation: were the expectations right, and why?
  5. Lessons: write what was new and what differed from expectations.
- Fair comparison needs the same train/test split and the same evaluation for every model.
- A Dummy that always predicts the majority class (<=50K) already gets ~76% accuracy. So **on imbalanced data, accuracy alone is not enough.**

### 2. Dataset: UCI Adult (Census Income)

- Use data from the well-documented UCI Machine Learning Repository.
- Goal: **binary classification** — from a person’s attributes (age, education, job, …), predict whether annual income is above or below 50K.
- Train 32,561 people, test 16,281, 14 feature columns + 1 target.
- The raw files need care:
  - No header row; names come from `adult.names`.
  - Values have a leading space (`39, State-gov, ...`).
  - Missing values are marked `?`.
  - The first line of the test file is a comment `|1x3 Cross validator`, not data.
  - Test labels end with a period (`<=50K.`). If left in, you get four label values.

### 3. Course models and this dataset

Models covered so far: Linear/Polynomial Regression, Perceptron, SVM, k-NN, Decision Tree, Naive Bayes.

| Model | What to watch on this data |
|---|---|
| Linear / Polynomial Regression | Issues using regression for binary labels; overfitting with polynomial degree |
| Perceptron | Failure to converge when data are not linearly separable |
| SVM | linear vs RBF kernel; training time on a large dataset |
| k-NN | Effect of scaling; curse of dimensionality; choosing k |
| Decision Tree | Overfitting with depth; interpretation via tree visualization |
| Naive Bayes | Effect when the “features are independent” assumption breaks |

- CNN is for data where neighboring values have meaning (e.g. images), so it does not fit this dataset.

### 4. EDA (Exploratory Data Analysis)

- Before modeling: **understand format and characteristics**.
  - Format: how the file is stored (delimiter, header, missing-value marker)
  - Traits: missing counts, class balance, distributions, mean/variance, relationships between features
- Do not read row by row; **summarize the whole set with code, tables, and plots**.
- Most important: interpret what findings mean for modeling. Those facts become the basis for explaining model results later.

### 5. How to organize the project

- **Folder layout:** shared code (data loading) in `src/`; analysis in notebooks. Copying the same code into many files invites mistakes and hard fixes.
- **Jupyter notebooks:** not required, but handy for keeping code, plots, and interpretation together.
- **`.gitignore`:** list of files not to upload to Git. Trimmed the template to what this project needs (Python cache, venv, model files, `.DS_Store`, etc.).

### 6. Virtual environment

- A project-local store of Python libraries.
- Homebrew Python blocks global installs, so `pip install` is refused without a venv.
- Avoids version clashes with other projects; `requirements.txt` can rebuild the same environment.

### 7. Data loading code (`src/data.py`)

- `Path(__file__).resolve().parent.parent`: find the project root from this file’s location so the path works no matter where you run from.
- `pd.read_csv` options:
  - `header=None`: first row is data.
  - `names=COLUMNS`: attach column names yourself.
  - `skipinitialspace=True`: strip leading spaces on values.
  - `na_values="?"`: treat `?` as true missing (NaN).
  - `skiprows=1`: skip the first line of the test file.

### 8. Lesson from a mistake: one missing column name

- Leaving `capital-loss` out of `COLUMNS` made 14 columns instead of 15.
- pandas **did not error**; it used the first value (age) as the row index and shifted every name by one.
  - So “age” held employment type, “workclass” held the weight, etc.
  - Missing counts also landed on the wrong features.
- **Takeaway:** no error ≠ correct. Right after loading, always check `df.shape` and `df.head()` against what you expect.
