### 2. Why an evaluation module (`src/evaluate.py`)

- Different scoring per model makes comparison unfair.
- Put CV, multiple metrics, test scoring, and saving in **one set of functions** every notebook uses.

### 3. Metrics (`CV_SCORING`)

| Metric | Meaning |
|---|---|
| accuracy | Fraction correct |
| balanced_accuracy | Mean of per-class recall (less fooled by imbalance) |
| f1 | Harmonic mean of precision and recall (mainly minority class) |
| roc_auc | How well ranking scores separate classes (0.5=random, 1.0=perfect) |
| average_precision | PR-AUC; more sensitive to the minority (`>50K`) |

- ~3:1 imbalance → **do not trust accuracy alone.** Dummy already ~76%.

### 4. Cross-validation (StratifiedKFold + cross_validate)

- One test look cannot tell luck from skill. Split train into 5 folds and score in turn.
- **Stratified:** keep high/low income shares like the full set in each fold; otherwise some folds have almost no `>50K` and scores swing.
- `shuffle=True` + `random_state=42`: shuffle then split; same folds on re-run.
- `cross_validate` fits/scores 5 times. Preprocessing inside the pipeline → **each fold learns preprocess on that fold’s train only** → less leakage.
- Return mean and std per metric. Small std means stable skill across folds.

### 6. Final test scoring (`evaluate_on_test`)

- CV = expected skill; test = the real exam.
- `fit` on **all** train, then metrics + confusion matrix on test.
- `_positive_scores`: scores for ROC-AUC / PR-AUC
  - Prefer class-1 probability from `predict_proba`
  - Else `decision_function` (Perceptron, SVM, …)
  - Check with `hasattr` first

### 8. Saving results (`save_results` / `load_results`)

- `results/<model_name>.json`: model name, CV summary, test metrics, confusion matrix, optional extra.
- `RESULTS_DIR.mkdir(parents=True, exist_ok=True)`: create folder if needed.
- `json.dump(..., indent=2, ensure_ascii=False)`: readable; non-ASCII safe.
- Later `99_comparison.ipynb` will load these for comparison.
