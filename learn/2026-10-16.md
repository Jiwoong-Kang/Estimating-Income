### 2. 평가 모듈(`src/evaluate.py`)을 만드는 이유

- 모델마다 다른 방식으로 점수를 매기면 비교가 공정하지 않다.
- 교차 검증, 여러 지표, 시험 채점, 결과 저장을 **한 파일의 함수**로 모아 두고, 모든 모델 노트북이 이것을 쓰게 한다.

### 3. 채점에 쓰는 지표 (`CV_SCORING`)

| 지표 | 뜻 |
|---|---|
| accuracy | 맞힌 비율 |
| balanced_accuracy | 두 클래스 각각의 맞힌 비율을 평균 (불균형에 덜 속음) |
| f1 | 정밀도(precision)와 재현율(recall)의 조화평균 (주로 소수 클래스 기준) |
| roc_auc | 순위 점수(확률/decision)로 두 클래스를 얼마나 잘 구분하나 (0.5=랜덤, 1.0=완벽) |
| average_precision | PR-AUC. 소수 클래스(`>50K`)에 더 민감한 곡선 아래 면적 |

- 불균형 데이터(약 3:1)라서 **정확도만 보면 안 된다.** Dummy만으로도 약 76%가 나온다.

### 4. 교차 검증 (StratifiedKFold + cross_validate)

- 시험 데이터를 한 번만 보면 “운”인지 알 수 없다. 훈련 데이터를 5조각으로 나눠 번갈아 채점한다.
- **Stratified**(층화): 각 조각마다 고소득/저소득 비율을 전체와 비슷하게 맞춘다. 안 그러면 어떤 조각에 `>50K`가 거의 없어서 점수가 들쭉날쭉해진다.
- `shuffle=True` + `random_state=42`: 섞은 뒤 나누고, 다시 실행해도 같은 분할이 나오게 고정한다.
- `cross_validate`가 5번 학습·채점을 돌린다. 파이프라인 안에 전처리가 들어 있어서, **각 폴드마다 학습 조각으로만 전처리를 배운다** → 데이터 누수 방지.
- 반환은 지표마다 `mean`(평균)과 `std`(표준편차). std가 작으면 조각마다 실력이 안정적이라는 뜻이다.

### 5. 로지스틱 회귀로 확인한 교차 검증 결과

| 지표 | mean | std |
|---|---|---|
| accuracy | 0.845 | 0.003 |
| balanced_accuracy | 0.758 | 0.006 |
| f1 | 0.648 | 0.008 |
| roc_auc | 0.900 | 0.002 |
| average_precision | 0.741 | 0.012 |

- 정확도는 Dummy(~76%)보다 높지만, 균형 정확도와 F1은 그보다 낮다 → **고소득자를 맞히는 쪽은 아직 약하다.**

### 6. 시험 데이터 최종 채점 (`evaluate_on_test`)

- 교차 검증 = “실력 예상”, 시험 채점 = “진짜 시험지”.
- 훈련 **전체**로 `fit`한 뒤, 시험 데이터로 지표와 혼동 행렬을 계산한다.
- `_positive_scores`: ROC-AUC / PR-AUC에 필요한 “고소득 쪽 점수”를 꺼낸다.
  - `predict_proba`가 있으면 클래스 1의 확률을 쓴다.
  - 없으면 `decision_function`(경계에서 얼마나 멀리 있는지)을 쓴다. 퍼셉트론, SVM 등에 필요.
  - `hasattr`로 기능이 있는지 먼저 확인한다.

### 7. 혼동 행렬 (confusion matrix)

```
[[TN, FP],
 [FN, TP]]
```

로지스틱 회귀 시험 결과: `[[11519, 916], [1575, 2271]]`

|  | 예측: 저소득 | 예측: 고소득 |
|---|---|---|
| 실제: 저소득 | TN = 11519 | FP = 916 |
| 실제: 고소득 | FN = 1575 | TP = 2271 |

- 저소득은 대부분 맞춤 (약 92.6%). 고소득은 1575명을 놓침.
- 정확도가 높은 이유: **다수 클래스(저소득)를 잘 맞춰서** 올라간 것이다.
- 네 칸 합 = 16281 (시험 인원과 일치).

시험 지표: accuracy 0.847, balanced_accuracy 0.758, f1 0.646, roc_auc 0.899, average_precision 0.736  
→ 교차 검증 평균과 거의 같아서, 운으로 한 번 맞은 게 아니라 비슷한 실력이다.

### 8. 결과 저장 (`save_results` / `load_results`)

- `results/<model_name>.json`에 모델 이름, 교차 검증 요약, 시험 지표, 혼동 행렬, (선택) extra를 저장한다.
- `RESULTS_DIR.mkdir(parents=True, exist_ok=True)`: 폴더가 없으면 만든다.
- `json.dump(..., indent=2, ensure_ascii=False)`: 사람이 읽기 쉽게, 한글도 깨지지 않게 저장.
- 나중에 `99_comparison.ipynb`가 이 파일들을 모아 모델을 비교한다.
- 확인용으로 `logistic_regression.json`을 만들었다. 나중에 로지스틱 노트북을 정식으로 돌리면 같은 이름으로 덮어쓰면 된다.

### 10. Dummy 기준선 (`02_dummy.ipynb`)

- Dummy는 **특징을 전혀 보지 않고**, 정답 중 가장 많은 쪽만 계속 예측하는 모델이다.
- `DummyClassifier(strategy="most_frequent")` → 여기선 전원 `<=50K`(0)로 예측.
- 역할: 다른 모델의 **바닥선**. “이것보다 못하면 학습이 의미가 없다.”
- 노트북 흐름은 앞으로 모델마다 비슷하다.
  1. `sys.path.append("..")`로 `src` import
  2. 데이터 나누기 (`split_features_target`)
  3. `make_model_pipeline`으로 조립
  4. `cross_val_scores` → `evaluate_on_test`(새 파이프라인) → `save_results`
